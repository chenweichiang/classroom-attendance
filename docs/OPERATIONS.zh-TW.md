# 課堂點名 操作手冊

下面的 `attend.example.edu` 請換成你自己的網域（`.env` 裡 `ATTEND_BASE_URL` 的那個）。老師端主頁 `https://attend.example.edu/t`（課程入口、上課流程、問題處理對照表都在這一頁），學生說明頁 `/help`（不用登入，可以貼給學生），學生備援輸碼頁 `/c`。老師密碼是伺服器 `.env` 裡的 `ATTEND_TEACHER_PASSWORD`。

安裝與部署看 [README](../README.zh-TW.md)；這份只講上課怎麼用。

## 每門課第一次上課：只做綁定

1. 在 `/t` 該課程按「只做綁定（第一次上課用）」，開投影頁。這一場開放 10 分鐘（名冊頁可調 3 到 30 分鐘），不記遲到與缺席、不計入出席率、結束不發 Discord，報表與 CSV 也不會出現這一場。
2. 學生掃 QR，填學號、中文全名、自設 4 到 6 位 PIN 兩次。點名頁看得到誰綁好了。
3. 綁定場次也可以抽點：叫到人不在，那個學號的綁定會被撤回（那筆綁定不是本人做的），而且那個學號今天不能再綁（解除綁定或重設也一樣），代綁的人重掃也綁不回去。按「不在」之前會跳確認框，寫出學號姓名與後果。本人下次上課再綁：點名頁先按開放「首次綁定」，請他掃碼設定。你若按錯「不在」，處理方式相同。作廢的綁定場次裡的抽點結果不算，學生當天可以重新綁。
4. 名單上標「待確認」的看一眼：同一支手機綁了兩個學號、姓名寫法與名冊不同（同字數、同姓，例如異體字）、或換瀏覽器改綁時姓名跟名冊不完全一樣的都會在這裡，當場問本人。最後一種多半是學號打錯、打到同姓同字數的同學，確認名單上那位是不是本人。
5. 這一場不能手動改狀態；第一次上課要留出缺勤紀錄，就在綁定結束後另開一場一般點名（學生此時已綁好，掃碼按一下就完成）。
6. 綁定場次還沒結束時按「開始點名」會被擋下來，先結束綁定場次。

## 每次上課（約 4 分鐘）

1. 筆電接投影機，瀏覽器開 `/t`，登入一次（30 天記住；在任何一台按登出，所有裝置都會登出）。
2. 該課程按「開始點名」，進入點名頁；按「開投影頁」，把那個分頁拖到投影幕全螢幕（Mac ⌃⌘F，Windows F11）。投影頁第一次載入會把這台的網路出口記成「教室 IP」；之後用手機開投影頁不會蓋掉，要改就在點名頁按「以這台為教室 IP」。這個值只是記錄用，不影響簽到與名單。
   投影頁：大 QR 每 10 秒換，換掉之後舊的那張還能用 30 秒；下方六位數同步換；右上「已簽到／全班」；左下剩餘分鐘。
3. 手機也開 `/t`，進同一場點名頁看名單（每 3 秒更新）。
4. 出席窗（預設 3 分鐘）到了自動關；還有人在簽就趁出席窗內按「延長出席窗」，出席窗剩不到一分鐘時計時旁會出現紅字「還有人在填就按延長」。出席或遲到看的是學生「掃到」的時間，不是送出的時間：窗內掃到、填到過窗才送出的人仍記出席。關窗後到遲到上限（預設 15 分鐘）仍可簽，記遲到；這時按延長只延遲到窗，晚到的不會變出席。
   點名頁的「簽到漏斗」顯示幾支手機掃到、幾支掃到時 QR 已過期、幾人送出、幾人成功；「卡住的人」列出連續被拒兩次以上的學生與原因，旁邊有「重設 PIN」鈕，點名字會把學號帶進最下方的手動簽到。人數不動時先看這兩塊，知道是哪一步在掉人。名單上標「掃碼被擋：（原因）」的人是掃過碼但還沒簽成功的，卡住名單三分鐘後就不列了，這個標籤會一直留到他簽成功或你手動處理為止。
5. 按「抽點 N 人」：畫面大字顯示學號與姓名，叫名看人，按「在」或「不在」。「在」會把待確認的人升成出席（在遲到區簽到的還原成遲到）；「不在」改缺席，用同一支手機簽的另一位一起改缺席並標「代簽連坐」；按「不在」會先跳確認框，按取消就不算。抽點要在按「結束」之前做完，結束後不能抽；待確認的裁定最好當場做，結束後也還能在名單上改。
6. 看「待確認」篩選：同一支手機簽了兩個學號時兩人都在裡面，當場問；放行選「出席」（名單標「遲到區簽到」的選「遲到」），否則選「缺席」。被放行的那位這次沒綁到手機，下次要簽時記得臨時開放首次綁定。
7. 請假的人先在名單上改成「請假」，再按「結束點名」：確認框會說還有幾支手機正在填表；確定後沒簽的自動記缺席，名單發到 Discord。結束後才改的，點名頁會出現紅字「名單發出後又改了 N 筆」，按「發到 Discord」發一份新的（舊訊息撤不回）。
   誤按結束：10 分鐘內按「取消結束」（結束鈕旁邊），結束時自動記的缺席會拿掉，已簽到的、你改過的都保留，學生可以繼續掃；出席窗被誤按切斷的，至少留到取消後 2 分鐘，遲到窗也至少留到取消後 2 分鐘（結束時已經在遲到區的，出席窗照原本時間）。取消後請剛才被擋的同學重新掃 QR，他們手機上停在「點名已結束」的畫面不會自己恢復。超過 10 分鐘、或這門課之後已經開了新的一場，就不能取消，晚到的人在名單上改狀態或用「手動簽到」補登；回主頁按「開始點名」時，上一場 10 分鐘內才結束的會先跳確認框提醒。「刪除此次」只用在誤開的點名：刪除會讓已拿到收據的人全部要重掃。
8. 整場出問題（投影壞掉、網路斷、多數人簽不進來）有兩個動作，都在結束後的點名頁：名單上方「自動缺席 N 筆：」那一列，下拉選好狀態再按「整批更正」，把系統自動記的缺席一次改成出席、遲到或請假（不動你手動設的與學生自己簽的）；「本場作廢」保留紀錄但不計入出席率、報表與 CSV 不出現，可以取消作廢。

## 網路不穩、投影頁出不來

投影頁連不上伺服器時會自己一直重試，並顯示已經連不上幾秒；點名頁也有一行「投影頁連線狀態」，紅字就是投影頁連不上伺服器。這種時候重新整理沒有用，照下面做：

1. 投影頁開了一分鐘還沒有 QR，就不要再等、也不要一直重新整理。
2. 可以試一次：用手機走行動網路開同一場的點名頁，再從那裡按「開投影頁」。手機上出得來，就把下方六位數唸出來，請學生開 `/c` 輸入（每 10 秒換一組，唸出後至少 30 秒內輸入都有效）。用完不要在手機上按「登出」：登出會讓所有裝置一起登出，教室電腦也會被登出。
3. 還是不行就改紙本或口頭點名。整場失敗時不要按「結束點名」，讓它過了遲到上限自己結案：自動結案時出席不到一半就不會發 Discord。點名進行中也可以先按「這場先不要自動發 Discord」，結案時就不會自動發，補完名單再按「發到 Discord」。
   只有一部分人簽不進來、多數人已經掃到時例外：出席過半，結案時照常發 Discord，紙本上的人會被列成缺席。這時要在遲到上限之前（點名頁還開著）就用點名頁的「手動簽到」把紙本上的人補進去，補完再按結束，或先按「這場先不要自動發 Discord」。
4. 課後開那一場的點名頁：名單上方「自動缺席 N 筆：」那一列，下拉選「出席」再按「整批更正」，再照紙本把真的沒來的人逐一改「缺席」、請假的改「請假」。整場不想算就按「本場作廢」。
5. 綁定場次失敗不用補救：綁定場次本來就不計出缺勤，下次上課再開一次「只做綁定」。
6. 事後把當天幾點、投影幕上看到什麼（空白、一直轉、錯誤訊息的原文）記下來，除錯時伺服器那邊看不到這些。

## 學生第一次

投影幕掃 QR，填學號、中文全名、自設 4 到 6 位 PIN 兩次，送出。這支手機從此綁定該學號（識別由伺服器以 cookie 下發，無痕模式或封鎖 cookie 會簽不了）。姓名與名冊字數相同、第一個字相同就放行（異體字不會被擋），但會標「姓名寫法不同」並轉待確認，等你看一眼。
第一週宣布：PIN 只在綁定與換手機、換瀏覽器時用，要記得、不給人；手機掃不過不要借同學的，直接舉手找老師；換了手機或瀏覽器，在新的那邊輸入原本的 PIN 就會自動改綁，忘了 PIN 才找老師；抽點不在就是缺席並記代簽嫌疑，用同一支手機幫忙簽的那位同一次也算缺席；修兩門課要各綁一次。

## 學生之後每次

掃 QR，頁面已顯示姓名，按一下就完成，不用輸 PIN（PIN 只在綁定、換手機或換瀏覽器、老師解除綁定之後才會用到）。相機掃不到就到 `/c` 輸投影幕上的六位數。代價是拿到別人已解鎖的手機就能替他簽，這一層靠抽點擋。

iPhone 上同一個人常常被認成「另一個瀏覽器」：從控制中心的掃碼器、LINE 或 Safari 私密分頁打開，每次都是新的 cookie。這種情況輸入原本的 PIN 就會自動改綁並照常記出席（名單標「換瀏覽器改綁」），不用找老師。代價是知道學號和 PIN 的人也能把綁定改走，所以抽點時可以多叫標了「換瀏覽器改綁」的人。

## 第一週之後：關掉首次綁定

綁定場次不受這個開關影響（一律開放）。全班綁定完成後，到「名冊與設定」把「首次綁定」關掉。之後沒人能用別人的學號綁走手機。新同學要簽時，在點名頁按「首次綁定：已關閉（按一下開放）」臨時打開，簽完再按一次關掉。這個開關只管從沒設過 PIN 的人。不受限制的有：已經設過 PIN 的人輸入原本的 PIN，不論是換手機、換瀏覽器，還是被你按過「解除綁定」（不論哪天按的），都會綁到新的那支；當天被你按「重設」的人（PIN 清掉了，當天可以重新設）。抽點判不在被撤回綁定的除外，那個學號今天不能再綁。

## Discord 自動通知

選用功能。在「名冊與設定」填該課的 Discord 頻道 ID、伺服器 `.env` 設好 `DISCORD_TOKEN`（bot 要有該頻道的發言權限）之後，按「結束點名」後，缺席、遲到、待確認名單（學號＋姓名）會自動發到該課頻道；沒收到就在點名頁按「發到 Discord」重發，兩分鐘內重複按、名單又沒變，不會真的再發一次。結束時出席不到一半的場次不會自動發（不論是你按的還是自動結案；多半是整場出問題，發出去就是公開的誤報），點名頁會顯示一行紅字，確認名單沒問題後再按「發到 Discord」。進行中可以按「這場先不要自動發 Discord」，結束時就不會自動發。自動發送失敗（bot 權限、頻道設定錯）點名頁會有紅字，主頁的場次列也會標「Discord 沒發出」或「暫緩中」；Discord 沒回應時紅字會提醒名單可能已經發出，先到頻道看再決定要不要重發。綁定場次與已作廢的場次不發、也不能手動發。要停用把頻道 ID 清空即可。名單含學號與姓名，頻道請設成只有修課學生與老師看得到。

## 學生自查

學生用最近一次簽到成功的那支手機或瀏覽器開 `/me` 就能看整學期出席率與每次紀錄，不用問老師。換瀏覽器改綁之後，舊的那個就看不到了。

## 備份

系統本身不做備份，請自己排程。資料庫是 `data/attend.db`（SQLite，WAL 模式），直接複製檔案可能拿到不一致的狀態，要用 SQLite 的線上備份取快照。容器的 `/tmp` 是 tmpfs、從外面讀不到，所以快照寫在 `/data` 底下，而且要用容器的服務帳號（uid 10001）做，用 root 開資料庫會留下 root 擁有的 `-shm` 檔：

```bash
cd /path/to/attend
docker compose exec -T -u 10001 attend python3 -c "import sqlite3; s=sqlite3.connect('/data/attend.db'); d=sqlite3.connect('/data/.snapshot.db'); s.backup(d); d.close(); s.close()"
gzip -c data/.snapshot.db > ~/backups/attend_$(date +%Y%m%d).db.gz && rm -f data/.snapshot.db
```

備份檔含學生個資而且是明文，放到雲端之前先加密，並訂好保留期限。還原：

```bash
cd /path/to/attend && docker compose stop
gunzip -c ~/backups/attend_YYYYMMDD.db.gz > /tmp/restore.db
sudo install -o 10001 -g 10001 -m 644 /tmp/restore.db data/attend.db
sudo rm -f data/attend.db-wal data/attend.db-shm /tmp/restore.db
docker compose up -d
```

## 系統自己會做的事

- 遲到窗過了沒按「結束點名」：自動結案並把沒簽的記缺席，報表照常，Discord 也會發（出席不到一半、或你按過「先不要自動發」的除外，見上），但發送時間是你下一次打開老師頁的時候。
- 抽點判「不在」：那位改缺席；若他是用別人的手機簽的，同一支手機簽的另一位也改缺席並標「代簽連坐」。
- 掃 QR 開出來的表單在開出來的當下就綁定那支手機，轉貼給別人一律被擋。能轉傳的只剩 QR 本身（最長 40 秒有效），這一層靠一機一人綁定與隨機抽點擋。
- 出席或遲到看這支手機本場最早掃到的時間：重掃、網路慢都不會把出席變成遲到；借別人手機簽到的人不繼承出借者的時間。
- 已結束的點名不能延長；誤按結束用「取消結束」，要再點名回主頁重新開始。
- 限流：六位數輸碼每支手機每分鐘最多輸錯 10 次、整個網路出口每分鐘最多輸錯 300 次（已綁定的手機不受出口上限影響）；掃 QR 開出表單每個出口每分鐘 120 次；簽到每支手機每分鐘 12 次、同一個出口的未綁定手機合計每分鐘 240 次，已綁定的手機不受出口上限影響。IPv6 以 /64 為一個出口計。
- PIN 錯誤次數：每支手機每場各自計（預設 3 次），同一個學號不分手機本場合計 20 次；同一個錯 PIN 一分鐘內重送只算一次，打對就清零。本人綁定的那支手機不驗 PIN，所以不會被鎖。
- 「IP 與教室不同」只存在資料庫，點名頁、報表與 CSV 都不顯示：老師與學生多半各用行動網路，出口本來就對不上。CSV 只有學號、姓名、班級與各場狀態，不含任何標記與 IP（要看標記到點名頁）。
- 同一場首次綁定滿 5 人之後，不再標「疑似同手機」與「同來源多筆首綁」（第一週全班同網路、同型號手機會人人亮），這段期間靠抽點。改綁不受這個限制，一律比對。
- 想知道系統看到的 IP 是什麼，開 `/api/ip`。

## 例外處理

| 情況 | 做法 |
|---|---|
| 手機沒電、沒手機 | 點名頁的「手動簽到」輸學號（卡住名單上的人可以直接點，學號會自動填好）。候選列會顯示他目前的狀態；已經是出席或遲到的人要改成別的狀態會先問一次 |
| 忘 PIN（平日不用輸，只有換手機、換瀏覽器或清過瀏覽器資料的人會遇到） | 卡住名單旁按「重設 PIN」，或名冊頁該生按「重設」（綁定、PIN 與本場的 PIN 鎖定一起清掉），請他重新掃碼當作第一次使用；當天不受首次綁定開關限制 |
| 名單標「PIN 鎖定」、學生看到「PIN 錯太多次」 | 這一場 PIN 錯太多次被鎖住。記得 PIN 的話等下一場；這一場走「手動簽到」。真的忘了就按「重設 PIN」，會一併解鎖，請他當場重掃設新 PIN。已經簽到成功的人不會再掛這個標籤 |
| 換手機或換瀏覽器 | 學生在新的手機或瀏覽器掃 QR、輸入原本的 PIN，就會自動改綁、照常記出席，名單標「換瀏覽器改綁」。不用到名冊頁處理；忘了 PIN 才按「重設」 |
| 學生看到「這個學號這一場已經有紀錄」 | 他這一場已經簽過（或你已經手動記了），又在另一個瀏覽器用這個學號打對 PIN。iPhone 每掃一次常換一個新環境，多半是本人又掃了一次：點名頁另起一行灰字「已有紀錄、又用新瀏覽器掃了一次（多半是本人，不用處理）」，不用理。只有用他原本綁定的那支被擋、或有人打錯 PIN 時才會在「卡住需要幫忙」出紅字，那時當場確認是不是本人 |
| 卡住名單出現灰字「剛處理過的同學又試了一次」 | 你剛手動記過或重設過的同學，10 分鐘內又打錯一次 PIN。多半就是站在你面前的本人，不用理 |
| 名單標「換瀏覽器改綁」 | 學生換了手機或瀏覽器、打對 PIN 自動改綁。知道學號和 PIN 的人也做得到，抽點時可以多叫這些人 |
| 名單標「掃碼被擋：…」 | 這位學生掃過碼但沒成功（原因寫在標籤上），目前還沒簽到。進行中就走過去看或手動簽到；結束後要整批更正之前，先看這些人 |
| 卡住名單出現紅字「本場剛綁定（或剛改綁），另一支手機（瀏覽器）又用這個學號簽」 | 這場先有一個瀏覽器用這個學號綁定或改綁，之後又有另一個用同一個學號被擋。當場叫名確認：兩邊都是他自己的，不用處理；不是他做的，就是有人知道他的學號和 PIN，按「重設 PIN」讓他當場重掃設新 PIN |
| 名單標「老師改後才掃碼」 | 你先把他記成請假或缺席，他之後才掃到碼。要不要改回出席由你決定 |
| 名單狀態欄顯示「開場後加選」 | 這一場開了之後才匯進名冊的人，這一場不算未簽到、也不算進出席率；他其實有來就在下拉改狀態 |
| 名單標「疑似同手機」 | 同一個網路出口、同一種手機型號（IP、瀏覽器、語言都相同），本場已經有另一個學號簽到成功，這個學號又在這時候首次綁定或改綁，一般點名會停在「待確認」，綁定場次只標記。可能是有人在私密分頁替別人綁定或改綁，也可能只是同型號手機剛好長得一樣；當場看一眼兩位是不是各拿一支手機，沒問題就放行 |
| 一個人標「裝置已綁他人」 | 這支手機曾用來首次綁定另一個學號，多半是代簽者的手機。到名冊頁看哪兩個學號綁在同一天，把不該綁的那個按「重設」（只按「解除綁定」的話，代綁的人設的 PIN 還在，換個瀏覽器又能綁回去） |
| 誤按「結束點名」 | 10 分鐘內按「取消結束」，見上面第 7 步。不要用「刪除此次」再重開 |
| 名冊頁按「解除綁定」或「重設」之後 | 跳出的提示會依情況說明：只解除綁定的，他之後用原本的 PIN 就會綁到新手機；重設的，他今天重新設 PIN 就能綁；今天在綁定場次被判不在的，今天不能再綁。確認框會寫出學號姓名，按之前看一眼是不是那一列。名冊頁上方有搜尋框，直接輸學號或姓名 |
| 剛加選、不在名冊 | 先在紙上記；課後更新名冊（下段）後回那次點名頁用「手動簽到」補登 |
| 網路壞掉、投影頁一分鐘沒有 QR | 見上面「網路不穩、投影頁出不來」；系統沒有離線或區網備援模式 |

## 出事時怎麼看紀錄

學生說「簽不到」、或名單跟你記得的不一樣時，下面三支都是唯讀、不印學號姓名。在部署目錄跑：

1. **一場點名裡誰卡在哪一步**（事件表＋簽到表，最常用）。容器的根目錄是唯讀的，所以把程式從標準輸入餵進去，參數接在 `python -` 後面：

   ```bash
   docker compose exec -T attend python - 9 < tools/session_report.py        # 第 9 場
   docker compose exec -T attend python - --last 3 < tools/session_report.py # 最近 3 場
   ```

   輸出：場次設定與開關時間、結果統計、各種事件次數、被拒原因、有被擋過的學生（S01、S02…）逐筆時間線、被擋過最後卻是自動缺席的人、「掃到了（認得是誰）卻沒有簽到成功」的人（結束後才送出、填表逾時、被限流、伺服器出錯）、老師的操作（延長、手動改狀態、解除綁定、重設、首次綁定開關、取消結束；刪除此次會留一筆「場次外」紀錄），以及沒對到場次但在開場前後 10 分鐘內的失敗（輸錯代碼、限流、前端回報的斷線）。被拒原因會附中文說明；「本場已有紀錄（打對 PIN）」不是被擋。
2. **從反向代理的存取日誌看漏斗**（伺服器有沒有收到請求、回了什麼）：`tools/log_funnel.py`，用法在檔頭。它的「裝置」欄是出口 IP 的雜湊，同一個校園網路後面的多支手機會併成一個，所以誰被擋一律以第 1 支為準，這支只看沒進到程式的請求。
3. **程式有沒有出錯**：`docker compose logs --since 24h attend 2>&1 | grep -c Traceback`。

學生看得到的失敗都會留一筆事件：簽到被拒（原因碼）、輸碼頁沒有進行中的點名、輸碼或自查被限流、表單格式錯、學生頁回錯誤、送出時斷線或認人失敗（前端回報）；老師的延長、手動改狀態（含整批更正）、解除綁定與重設、首次綁定開關、取消結束也都有時間紀錄。

## 名冊更新

1. 本機整理 CSV（欄位 student_id、name、class），放 `data/rosters/`（這個目錄不進版控）。`scripts/parse_rosters.py` 是範例：`python3 scripts/parse_rosters.py --nthu-csv 選課名單.txt --ntub-xls PoolExport.xls`（處理兩種台灣學校的匯出格式）。別的學校照自己的匯出格式改。
2. 先用 `--dry-run` 看會新增、更新、刪除幾人，再正式匯入（重複執行安全：同學號只更新姓名班級，不動 PIN 與綁定；加 `--prune` 才刪名冊裡沒有的人）：

```bash
cat data/rosters/demo.csv | ssh 你的主機 'cd /path/to/attend && docker compose exec -T attend python manage.py import-roster --code DEMO --name "示範課程" --csv /dev/stdin --dry-run'
cat data/rosters/demo.csv | ssh 你的主機 'cd /path/to/attend && docker compose exec -T attend python manage.py import-roster --code DEMO --name "示範課程" --csv /dev/stdin'
```

不寫進伺服器磁碟。匯入會先把整份檔案檢查完才寫，任何一項不過就什麼都不改，並印出每一個有改名或改班級的學號。幾種情況會停下來要你加 `--force`：已綁定或已設 PIN 的人改名（先確認是正式改名，不是匯出檔截字或打錯）、`--prune` 要刪的人超過名冊一成、要刪與要新增的人同名（多半是換學號，簽到紀錄會跟著舊學號一起刪）、課程代碼疑似打錯。新姓名是舊姓名的較短前綴、學號不是英數字，這兩種要先修 CSV，`--force` 也不放行。

有人退選、確定要從名冊拿掉時才加 `--prune`（先用 `--dry-run` 看他有幾筆簽到紀錄）。名冊有新同學時，姓名用字可能不在自架仿宋字型裡，收據上那幾個字會退回系統明體；要補就跑 `tools/subset_font.py`（說明在檔頭）再部署，字型網址帶內容雜湊，部署後立即生效。

課程代碼（`--code`）自己取，英數字即可，例如 `DEMO`；`python manage.py list` 會列出現有的課程、名冊人數與已綁定人數。

## 學期末

先把每一場的「待確認」裁定完（沒裁定的不算出席但算分母），再到「學期報表」看出席率，「下載 CSV」登校務系統。報表裡每一場的日期都連到那一場的點名頁，主頁也有「全部場次」。

要清資料有兩種：只刪某門課（保留其他課與綁定）用 `docker compose exec -T attend python manage.py delete-course --code DEMO`；整個清空（所有課、名冊、綁定、PIN 都消失，下學期重匯名冊、全班重綁）：

```bash
cd /path/to/attend && docker compose stop; sudo rm -f data/attend.db data/attend.db-wal data/attend.db-shm data/.snapshot.db*; docker compose up -d
```

data 目錄是容器帳號 10001 的，不用 sudo 刪不掉。**學期中絕對不要更換伺服器 .env 裡的 ATTEND_SECRET**：裝置雜湊用它衍生，一換全班綁定同時失效；要讓老師 cookie 失效用「登出」即可。

## 設定可調

名冊頁最上面：開放分鐘、遲到上限、綁定場次分鐘、QR 秒數、過期容許秒數（預設 30）、抽點人數、IP 比對開關、Discord 頻道。遲到上限要比開放分鐘多幾分鐘：兩個一樣的話，最後一刻掃到、送出時剛好結束的人沒有遲到區可掉，會直接記缺席。點名進行中不要改 QR 秒數：已經顯示的 QR 與六位數會立刻失效。每門課各自一組。預設值只對新建的課生效；已經存過設定的課要自己改，或用 `manage.py set --code 課程代碼 --key qr_grace --value 30`，超出範圍的值它會拒絕並印出實際會生效的數字。各鍵的範圍見 README 的設定表。
